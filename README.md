# 🏗 ИИ-ассистент отдела продаж стройматериалов

> **Умный Telegram-бот с гибридной архитектурой, автоматическим расчетом цен, логистики и строгим соблюдением 152-ФЗ.**

Этот репозиторий содержит исходный код, конфигурацию воркфлоу и техническую документацию выпускного проекта. Система автоматически обрабатывает запросы клиентов, определяет их статус (розница/опт), рассчитывает стоимость товаров и доставки без галлюцинаций ИИ, используя методологию **SQL-RAG**.

## 💡 О проекте и решаемая проблема

Менеджеры торгово-дистрибьюторских компаний тратят до 40% времени на рутину: проверку прайс-листов, уточнение остатков и ручной расчет логистики. Это приводит к задержкам ответов (до 12 часов) и потере «горячих» лидов.

**Решение:** Telegram-бот, который за **< 15 секунд**:
1. Идентифицирует клиента по `chat_id` и применяет персональную скидку.
2. Находит товар в базе даже при опечатках (Full-Text Search + Trigram).
3. Рассчитывает точную стоимость доставки по регламенту (РФ и СНГ).
4. Формирует вежливый, персонализированный ответ через нейросеть GigaChat.

## 🛠 Технологический стек

- **Оркестрация:** [n8n](https://n8n.io/) (Self-hosted, Docker)
- **База данных:** PostgreSQL 16 (с расширениями `pg_trgm` для нечеткого поиска)
- **Языковая модель:** GigaChat API (OAuth 2.0 авторизация)
- **Веб-сервер:** Nginx (Reverse Proxy + Let's Encrypt SSL)
- **Язык скриптов:** JavaScript (в нодах Code для маскирования ПДн и сборки промптов)

## 🧠 Как работает SQL-RAG в этом проекте

В отличие от классического векторного RAG, который может давать погрешности в цифрах, данный проект использует **Structured SQL-RAG** для финансовых данных:

1. **Извлечение:** n8n парсит сообщение пользователя (например, *"50 мешков цемента в Бишкек"*).
2. **Поиск (SQL):** Параллельные запросы к БД в Москве:
   - Поиск клиента по `chat_id`.
   - Поиск товара через `ILIKE` и `similarity()` (устойчиво к опечаткам).
   - Поиск правил доставки через полнотекстовый индекс (`to_tsvector`).
3. **Сборка контекста:** JavaScript-нода собирает точные цифры (цена, остаток, стоимость доставки) и формирует жесткий системный промпт.
4. **Генерация:** GigaChat получает готовые цифры и **запрет на математические вычисления**. Его задача – только вежливо оформить ответ.

*Это гарантирует 100% точность расчетов и полное отсутствие галлюцинаций ИИ в ценах.*

## 🔒 Безопасность и соответствие 152-ФЗ

- **Локализация данных:** Вся база данных с ПДн физически находится на сервере в РФ.
- **Маскирование в логах:** Перед записью в таблицу `dialogue_logs` `chat_id` алгоритмически маскируется (например, `174236684` → `174****684`).
- **Минимизация контекста:** В запрос к GigaChat **никогда** не передаются ИНН, email или полные номера телефонов клиентов.
- **Авторизация:** Оптовые цены и условия выдаются только после успешной сверки `chat_id` с таблицей авторизованных дистрибьюторов.

## 📊 Метрики и оценка стоимости

Система ведет детальный лог каждого диалога в таблице `dialogue_logs` (на сервере в РФ), автоматически фиксируя:
- **Маскированный ID клиента** (например, `174****684`) для соблюдения 152-ФЗ.
- **Использованные токены** (`tokens_used`) для точного пост-фактум расчета затрат на LLM.
- **Тип клиента** (розница/опт) и **канал связи** для последующей аналитики.

### 💰 Пример из реальной работы (на основе собранных логов):
- **Средний расход:** ~450–520 токенов на один полноценный запрос с извлечением сущностей и расчетом логистики.
- **Себестоимость диалога:** При текущем тарифе GigaChat это обеспечивает стоимость обработки одного запроса **менее 0.20 ₽**.
- **Бизнес-эффект (ROI):** Решение полностью окупается за счет высвобождения **~1.5 часов** рабочего времени менеджера в день. Это позволяет перенаправить человеческие ресурсы с рутинных консультаций на закрытие сложных B2B-сделок.
